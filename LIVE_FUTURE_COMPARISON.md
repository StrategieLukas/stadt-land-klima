# Production / Future visual comparison

Compared **224 distinct public paths in 896 site/viewport captures** on 4 November 2026: [production](https://stadt-land-klima.de/) (redirects to `www`) and [Future](https://future.stadt-land-klima.de/). This compares the two deployed websites, rather than substituting the local development database for either site. The participation fix described below is a local source change and has not been deployed.

The side-by-side [screenshot gallery](.reports/live-future-2026-11-04/index.html) contains desktop (1440 × 1000) and phone (390 × 1000) captures, with production on the left and Future on the right. The accompanying [route inventory](LIVE_FUTURE_ROUTE_INVENTORY.md) records each discovered URL, response status, content/layout differences and screenshot links. German and light mode are the comparison baseline. The local participation change was additionally checked in dark mode and at 320px and 768px.

The visited paths include 48 project/tour routes, 45 measure/sector routes, 32 municipality routes, 28 election routes, 14 news routes and 12 event routes, plus the CMS pages and representative data, region, statistics and embed routes. The full inventory distinguishes real pages from aliases, missing links and shared empty routes. Screenshot files remain local under the ignored `.reports/` directory.

“Likely deliberate” identifies an apparent redesign or added feature, not a claim that the owner has approved every detail. “Review” identifies a visible difference that needs a design/content decision. Shared changes apply to the detail pages as well as their directory pages.

## Main decisions and deviations

- **Fixed locally:** `/mitmachen` uses six styled numbers instead of unrelated icons, with each heading and description in one naturally wrapping text column.
- **Confirmed phone defect:** Future's `/ki` sector table makes a 390px viewport scroll to approximately 540px wide. The table needs containment or a responsive layout; production has no equivalent page.
- **Review reading width:** common CMS pages widen from 650px to 768px, while the participation block expands to 1232px. This changes image scale and line lengths substantially.
- **Review visual hierarchy:** neutral active navigation, a shorter footer, larger filter pills, horizontal news/event timelines and less visible job-card outlines are visible design choices, not exact production parity.
- **Content/routing follow-up:** the November workshop is absent from Future; the encoded Wahlcheck sitemap URL is invalid; both sites retain several broken authored links and an empty sector-index route.

## Content and routing differences that affect the comparison

- Production lists the upcoming **24 November 2026 Klimawerkstatt**. Future's event directory says there are no upcoming events, and its corresponding `/events/klimawerkstatt-24-11-2026` URL returns 404. This also removes a card/section from the Future news feed. This is a content/publication difference, not a card-layout CSS change.
- Ranking/statistics totals, place order and some feed entries differ between the two databases. For example, the desktop statistics totals and Arnsberg's rank differ. These are not classified as styling regressions.
- Both sites expose broken internal links such as `/evets`, `/kontakt`, `/impact-training`, `/id3` and `/echo` in authored/navigation content. These are shared defects rather than Future-only deviations. Exact discovered statuses are recorded in the inventory.
- Future's sitemap advertises `/elections%2Fwahlcheck`, which returns 404; the correctly separated route `/elections/wahlcheck` works. Production's encoded URL returns an empty-content page. This is a routing/discovery issue.
- Production's `/sitemap.xml` returns 404; Future provides a sitemap. The crawl therefore uses Future's sitemap plus the union of internal links from both sites.

## Participation change implemented locally

`useCmsHtml()` no longer imports/injects unrelated icons for the six steps. The checked legacy renderer retains visible step numbers and moves the existing step heading into the text column beside each number. Manual `<br>` elements within the step descriptions become spaces, so the available width determines wrapping. Other page content, links, step IDs and the HTML sanitizer remain in place.

Each number uses a 40px brand-green (`#AFCA0B`) badge, condensed bold type, a dark border and a small offset shadow. The row uses a fixed badge column, a shrinking text column, a responsive gap and a 768px maximum reading width. The existing page-wide participation layout is not redesigned in this change.

Implementation: `src/frontend/utils/legacyCmsHtml.ts`, `src/frontend/composables/useCmsHtml.ts`, `src/frontend/assets/css/main.css`. Targeted regression: `bin/test_suite/src/cmsOrigin.test.ts` — “legacy participation steps keep numbered heading/text rows and nested authored sections without forced breaks”. `FEATURES.md` records this coverage.

The local database has different authored participation content, so the browser geometry check renders the captured Future participation HTML through the actual updated renderer inside the running local application's stylesheet. It checks all six visible numbers, badge dimensions/color, heading placement, absence of step icons/manual breaks and document overflow at 320/390/768/1440px in light/dark mode. This is fixture-based local verification, not a claim that Future already serves the change. The gallery includes the local after-captures.
